# Tcl/Tk

Proyectos en **Tcl/Tk**, con scripts independientes ejecutados mediante `tclsh` y proyectos tipo librería probados con **Tcltest**. Tk queda disponible para futuras prácticas de interfaces gráficas.

---

## 📂 Módulos / Modules

| Módulo | Descripción |
| ------ | ----------- |
| [`core/foundations/`](core/foundations/) | **Fase 0 — Fundamentos**: `helloworld`, `hellouser`, `unit_test/calculator`, `numbers` |

---

## ▶️ Comenzar / Getting Started

```bash
# Cargar Tcl instalado en el usuario
source "$HOME/.bashrc"

# Hello, World!
cd core/foundations/helloworld
tclsh9.0 hello_world.tcl

# Hello, User!
cd ../hellouser
printf 'Ada\n' | tclsh9.0 hello_user.tcl

# Calculator tests
cd ../unit_test/calculator/test
TCLLIBPATH="$(cd ../src && pwd)" tclsh9.0 calculator.test

# Numbers tests
cd ../../numbers/test
TCLLIBPATH="$(cd ../src && pwd)" tclsh9.0 recursive.test
TCLLIBPATH="$(cd ../src && pwd)" tclsh9.0 iterative.test
```

```bash
source "$HOME/.bashrc"
tclsh9.0 <<< 'puts [info patchlevel]'

```

## 🏗️ Tipos de proyecto / Project Types

### 1. Programa independiente (`tclsh`)

**ES:** `helloworld` y `hellouser` son scripts `.tcl` ejecutados directamente con Tcl. No necesitan sistema de build ni dependencias externas.

**EN:** `helloworld` and `hellouser` are `.tcl` scripts run directly with Tcl. They need no build system or external dependencies.

```bash
tclsh9.0 <File>.tcl
```

### 2. Proyecto tipo librería con Tcltest

**ES:** `calculator` y `numbers` separan `src/` y `test/`, registran paquetes con `pkgIndex.tcl` y cargan el código mediante `TCLLIBPATH`. Tcltest proporciona el runner y el reporte.

**EN:** `calculator` and `numbers` separate `src/` and `test/`, register packages with `pkgIndex.tcl`, and load code through `TCLLIBPATH`. Tcltest provides the runner and report.

## 🔁 Decisión de TCO / TCO Decision

Tcl tiene iteración nativa mediante `for` y `while`, pero no ofrece una garantía general de Tail Call Optimization en este proyecto. Por eso `numbers` conserva `_acc` como puente didáctico sin suite propia y prueba `_rec` e `_ite`:

Tcl has native iteration through `for` and `while`, but does not provide a general Tail Call Optimization guarantee in this project. Therefore `numbers` keeps `_acc` as an educational bridge without a dedicated suite and tests `_rec` and `_ite`:

```text
TCO no garantizada + iteración nativa ✅
_rec + _ite
2 suites
10 tests
22 casos
```

---

## 🧪 Convenciones de pruebas / Testing Conventions

**ES:** Tcltest está incluido en la distribución de Tcl. Las suites viven en `test/`, cargan paquetes de `src/` con `TCLLIBPATH` y agrupan los casos por algoritmo.

**EN:** Tcltest is included in the Tcl distribution. Suites live under `test/`, load packages from `src/` through `TCLLIBPATH`, and group cases by algorithm.

---

## 🧹 Artefactos de ejecución / Runtime Artifacts

Los `.gitignore` locales excluyen los logs generados por Tcltest. Los scripts independientes no generan artefactos de compilación persistentes.

Local `.gitignore` files exclude logs generated by Tcltest. Standalone scripts do not generate persistent build artifacts.
